1. Affirm Single-Task Delivery Contract

Inspired by Affirm's engineering organization retooling for agentic development:

The Golden Contract: 1 Task → 1 Agent Session → 1 PR with explicit human checkpoints around planning and final review.
  • Bounded Scope: Never let an agent session wander into unbounded feature sprawl or tangential refactoring.
  • Deterministic Artifact: Every successful task culminates in a clean git branch (brief/) and a well-described Pull Request.
  • Human in Control: Autonomous coding happens within boundaries, but humans retain architectural authority and merge decisions.

2. The Ponytail Laziness Ladder

Before an agent writes any new code or introduces dependencies, it must ascend the Ponytail Decision Ladder:

Level 1 YAGNI (You Ain't Gonna Need It) Does this code need to exist? If not strictly requested, drop it.
Level 2 Standard Library First Can Python/Node stdlib do it? (pathlib, itertools, crypto, fetch).
Level 3 Native Platform / Browser Feature Use native HTML/CSS/DOM APIs instead of third-party widget packages.
Level 4 Existing Project Dependency Reuse what is already installed in pyproject.toml or package.json.
Level 5 Clean One-Liner Can it be written in a single clean idiomatic expression?
Level 6 Minimal Surgical Code Only then write the minimum required implementation. Zero speculative abstractions.

3. Karpathy Grounding Disciplines

🧠 Think Before Coding

State assumptions explicitly. Surface trade-offs before editing. If requirements are ambiguous, stop and ask rather than guessing silently.

🎯 Simplicity First

Write the minimum code to solve the active issue. Zero speculative abstractions, single-use helper classes, or pre-emptive configurability.

✂️ Surgical Changes

Touch ONLY lines necessary for the test to pass. Never reformat adjacent code, adjust unrelated comments, or delete untouched dead code.

🧪 Goal-Driven Execution

Transform every task into an automated test. Write or run the failing test (Red), implement the patch (Green), verify deterministically.

4. Multi-Agent Pragmatism (Single-Agent Default)

Core Rule: Use 1 agent by default. Never spin up multi-agent swarms simply because they are possible.

Introduce secondary agents ONLY when there is a concrete technical reason:

Task Scenario Agent Structure Justification
Normal Bug / Feature 1 Agent + Local Tests Lowest latency, zero coordination token overhead.
Major Architecture Shift Planner → Coder Read-only plan mode prevents dirtying the repository before approval.
High-Risk Core Changes Coder → Independent Reviewer Adversarial second opinion using a different strong model.
Security-Sensitive Work Coder → Strix AI (Sandbox) → Fixer Dynamic PoC vulnerability validation in isolated worktree.
Parallel Independent Tasks Orchestrator → Worktree Swarms Physical directory isolation preventing merge conflicts.

5. Task Sizing & Cline Plan/Act Split

Every engineering task is classified into one of three sizes:

S — Small

Direct Act Mode

Typos, single-file bug fixes, test additions (<20 lines touched).

  • No planning document needed
  • Immediate surgical patch
  • Deterministic test verify
M — Medium

Plan → Act Mode

Standard features, API routes, component builds (20–150 lines).

  • Draft implementation_plan.md
  • Human approval gate
  • Fleet Loop execution
L — Large

Research → Spec → Worktree

Architectural shifts, new subsystems, migrations (>150 lines).

  • Socratic /grill-me interview
  • Isolated git worktree
  • Subagent execution & review

6. Universal End-to-End Workflow

1

Task Ingestion & Notion Pull

Task pulled from Notion Kanban (status Ready) or CLI brief. Classified as S, M, or L.

2

Planning & Human Gate (M / L)

Agent enters Plan Mode. If ambiguity exists, /grill-me resolves the decision tree. Human approves implementation plan.

3

Worktree Isolation & WORKING.md

Provisions physical worktree brief/ and initializes WORKING.md scratchpad.

4

Fleet Loop TDD Execution

Red-Green-Refactor loop with Ponytail ladder constraints and deterministic test runners.

5

Security Review (Strix AI) & Code Review

Security audit for sensitive endpoints in sandbox, followed by independent AST diff review.

6

PR Creation & Notion Sync

PR opened via gh pr create, Notion status transitions to In Review. Human merges and moves to Done.

A bounded, multi-stage adaptive verification engine replacing naive infinite fix loops:

Circuit Breaker Rule: Maximum 3 retry attempts. If the 3rd attempt fails, the loop terminates immediately, logs the failure in WORKING.md, and alerts the engineer. Zero token burn on endless loops.

9. Security Sandbox Review (Strix AI)

Security-sensitive operations are audited in an isolated sandbox with automated Proof-of-Concept validation:

  • Isolated Worktree: git worktree add ../sec-review-sandbox -b sec/audit
  • SAST Pre-Scan: Semgrep / Bandit / ESLint Security scanner.
  • Strix AI Attack Agent: Automated testing against OWASP Top 10 (Injection, BOLA/IDOR, Auth/JWT flaws, SSRF).
  • PoC Verification: Fixes are only approved once Strix confirms the PoC no longer reproduces.

10. Notion Kanban Integration

Replaces legacy Microsoft Planner with Notion Kanban database synchronization:

Notion Database Schema

  • Task Name (Title)
  • Status: Backlog, Ready, In Progress, In Review, Done, Blocked
  • Mode: AFK, HITL, Clarification
  • Size: S, M, L
  • Priority: P0, P1, P2, P3
  • Branch & PR Link

Sync Invariants

  • Agent Terminal State: In Review
  • The Done Gate: Only the human engineer transitions cards to Done after PR merge.
  • Notion MCP: Standard tool call integration with local caching in WORKING.md.

12. Universal Project Initializer (`init-project`)

Bootstrap any new or existing repository with full Antigravity guardrails in seconds:

# Run from your target repository root:
d:\projects\antigravity_setup\scripts\init-project.ps1 -ProjectName "my-project" -ProjectType "python" # or "typescript" / "fullstack"

This automatically installs:

  • .agents/rules/global_rules.md (Ponytail, Karpathy, Affirm contracts)
  • AGENTS.md and CONSTITUTION.md
  • WORKING.md active task scratchpad
  • scripts/verify.ps1 deterministic test gate
  • .githooks/pre-commit verification hook
